# Frozen-pass model survey — 2026-11-18

The current C++ legalization engine was held fixed. All six candidates are
absent from the official SDK 3.1 tutorial inventory at commit
`f5a428c3c0ee7e06ad06657c5fcdcc1eda8cf046` and from the frontend's verified-model
table. Absence from tutorials does **not** prove that the SDK cannot support them.
This survey checks ONNX export, rewriting and CPU execution only; it does not
establish TFLite/VNNX compilation, accelerator support or board latency.

## Interpretation

- **MobileViT-XXS** is the most promising first follow-up among the rewritten
  models when CPU overhead matters: latency is approximately unchanged. The
  small timing difference is not evidence of a speedup.
- **DeiT-Tiny, DINOv2-Small and SegFormer-B0** preserve sampled outputs after
  rewriting, but CPU inference is slower. These passes target SDK-compatible
  operator forms, not ONNX Runtime CPU optimization.
- **SuperPoint** has zero rewrites and byte-identical before/after ONNX files.
  Its observed timing difference is measurement variation, not a compiler gain.
- **LightGlue** fails during PyTorch 2.3.0 ONNX export with `IndexError: list
  index out of range` in the transpose symbolic. The C++ pass is never reached;
  no claim about downstream support or latency can be made.

These are general vision/localization components relevant to robotics and
image-analysis pipelines, not aerospace/defense-specific trained systems.
Synthetic input agreement does not establish accuracy on operational imagery.
No additional models were added to the main README's verified-model list.

## Measurement conditions

- Intel Core i7-1355U; ONNX Runtime 1.18.1 CPUExecutionProvider; FP32, batch 1.
- Two intra-op threads, one inter-op thread, sequential execution.
- Before/after numerical comparison: graph optimizations disabled, three
  reproducible input samples, `atol=1e-4`, `rtol=1e-3`; integer outputs exact.
- Latency: graph optimizations enabled for both models, five warmups, thirty
  timed `session.run` calls each, alternating before/after order. Reported values
  are medians; p95 and individual samples are retained in the JSON report.
- Loading, export, rewriting and preprocessing are excluded from inference time.
  This was a shared development PC without frequency locking; small differences
  should not be interpreted as improvements.
- The export was checked against PyTorch before applying the C++ pass. Static
  ONNX shape inference supplies metadata; it does not add legalization rules.
- SuperPoint measures dense outputs only, excluding sparse NMS/tracking.
  LightGlue attempted fixed-size matching with adaptive stopping/pruning and
  flash attention disabled. DINOv2 uses reduced 224×224 feature extraction.
